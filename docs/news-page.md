# ニュース画面

ニュースの採点から出した市場評価（センチメント・リスク）と、その材料を見る画面（`/news`。旧名「AI判定」の `/ai` は `/news` へ転送する）。設定（評価ルール・プロンプト・取得）は設定画面の「ニュース」区分に置き（`docs/settings.md`）、ニュース画面の右上の「設定」から開く。取得・採点・集計の仕様は `docs/news.md` と下の「集計」。

## 集計

- 判定は保存せず、見るたびに採点済みの点数から計算する。評価ルールを変えると、過去の判定もそのルールで計算し直す
- 評価時刻より後に採点した点数は使わない。新しさは公開時刻で測る（取得時刻より後なら取得時刻）
- 期間内の点数を、半減期ごとに重みが半分になる加重平均にし、整数に丸めて評価基準の範囲に当てはめる。null（関係なし）は入れない。対象が無い観点は中立（0・平常）
- 評価ルール（期間・半減期は 1〜168 時間の整数、評価基準の下限は観点の点数の範囲の整数。センチメントは -100〜100、リスクは 0〜100）は、下限が上の値ほど大きい順（センチメントは 強い強気 > やや強気 ≧ 中立 > やや弱気、リスクは 危機 > 警戒）でなければ保存できない。中立だけは やや強気 と同じ下限にでき、そのとき中立は範囲なし
- 評価の値は画面では日本語名（強い強気・やや強気・中立・やや弱気・強い弱気、平常・警戒・危機）で出す。保存する値は +2〜−2・normal など

## 画面

- タブ（スマホの下部）は ホーム・バックテスト・戦略・ニュース・その他。インポート・エクスポート・設定はスマホでは「その他」の中、PC ではサイドバーに置く。戻るボタンは置かない（どの画面も下部タブかサイドバーから開ける）
- 動いているアプリのバージョン（Docker イメージのビルド日時、例: Ver 2026-09-27 09:10）を、PC はサイドバーの下端、スマホは「その他」の下に出す。開発中は「Ver 開発版」
- PC のサイドバーは上端のボタンでアイコンだけの細い帯に畳める。畳んだ間は項目名をマウスを乗せたときに出し、実行中の印はアイコンの右上、バージョンは隠す。畳んだかどうかはブラウザに保存する
- 機能の仕組みの説明は画面に常に出さず、見出しの横の「？」を押したときに吹き出しで出す（外側を押す・スクロールで閉じる）。常に出すのは警告・空のときの案内・値など、今の状態を知らせる文だけ
- カード（枠で囲んだまとまり）には見出しを付ける。入力欄だけのカードは入力欄の名前を見出しの代わりにする
- 上部に見出し「今の市場評価」（集計の説明は横の「？」）、今の評価2つ（評価・平均点・何件から算出・評価基準の帯と、その下に色の意味の凡例1行）と時点。ニュースを日付で絞り込み、その終わりが今より前なら、見出しを「過去の時点の市場評価」にしてその終わりの時点の評価を出す
- 取得・採点が止まっている間だけ、判定の下に何が起きたかといつからかを出す。一部の取得元だけ失敗しているときも取得元ごとに出す。直すための設定のタブへのリンクを添える（取得は「取得」、採点は「プロンプト」）
- 5秒ごとに判定・ニュース・取得と採点の状態を問い合わせる。画面が見えていない間は止める
- 判定の下にニュースごとの採点を並べる

### 絞り込み

- ニュースごとの見出しの下に、キーワードの欄と「絞り込み」ボタン（キーワード以外で変えている条件の数を添える）、その下によく使う条件のチップを1行（横にスクロール）: 24時間・7日・強気材料・弱気材料・リスク高。日付を指定している間は先頭にその日付のチップ。押すと切り替わる
- 「絞り込み」のモーダルで 期間（すべて・24時間・7日・日付を指定。日付は JST の開始日〜終了日で、終了日の終わりまで）・影響の大きさ・並び順（新しい順・影響の大きい順）を選び、「この条件で見る」で反映する。「条件をクリア」はキーワード以外を戻す
- 期間は公開時刻で測る。キーワードは空白で区切った語をすべて含むもの（見出し・概要・採点の理由のどれかに。英字の大小は区別しない）。打ち終えてから問い合わせる
- 影響の大きさは今の評価基準で測り、選んだどれかに当てはまる採点済みのもの。強気材料=センチメントがやや強気の下限以上、弱気材料=中立の下限未満（やや弱気以下）、リスク高=リスクが警戒の下限以上
- 影響の大きい順は、センチメントの点数の絶対値とリスクの点数（関係なしは 0）の大きい方で並べる。採点済みでないものは最後
- 条件は URL（`?period=&from=&to=&impact=&sort=&q=`）に持つ。条件の下に当てはまる件数。置き換えを待っている採点し直しがあればその件数も添える
- 件数の横に「この N 件を採点し直す」。確認のモーダル（使用中の版・置き換えること・使い始める時刻は変えないこと・かかる時間の目安）を経て、条件に当てはまるものをまとめて採点し直す。1000件を超える間は押せず、絞るよう出す
- 絞り込みはサーバーで行い、全期間のニュースから探す

### ニュースごと

- 100件ずつ出し、続きは「さらに読み込む」（1000件まで）。新しい順のときは日付（JST）ごとに区切り、各ニュースには時刻だけ出す
- 公開時刻・取得元・見出し（原文、記事へのリンク）
- 採点済み: 観点ごとの点数（— は関係なし）と理由の1行目。「詳しく」で理由の全文・採点時刻（採点し直して置き換えたものはその時刻も）・版・モデル・採点したアプリのバージョン（記録前のものは「記録なし」）・集計での重みを開く。期間外は「集計の対象外」
- 採点し直し: 使用中と別の版で採点したものは「詳しく」の中に「vN で採点し直す」（N は使用中の版）。押すと運用の採点を置き換える（`docs/news.md` の運用の採点の置き換え）。待っている間は「vN で採点し直し中」、失敗して止まったら理由と「採点し直す」ボタン
- 未採点: 採点中（採点が止まっていれば「未採点」）。再試行待ち: 失敗の理由と次の自動再試行の時刻。採点に失敗: 理由と再試行ボタン。古いため採点しないもの: 集計の対象外

## 設定画面の「ニュース」区分

設定画面（`/settings?section=news`）の「ニュース」区分は、さらに 評価ルール・プロンプト・取得 のタブに分ける。表示中のタブは URL（`?tab=`）に持つ。取得の状態を5秒ごとに問い合わせる。

### 評価ルール

- 「平均のとり方」（期間・半減期）と「評価基準」を編集する。入力の誤りは項目の下に出し、保存できない
- 評価基準は評価の値ごとに、上から「下限 〜 上限 点」の重ならない範囲で出す。入力するのは下限だけで、上限は1つ上の値の下限−1 を自動で出す。一番下の値（強い弱気・平常）の下限は点数の範囲の下端で固定
- 入力が正しい間は「この設定での今の市場評価」を出す（保存しない）
- 元に戻す・保存。保存すると次の評価から反映する

### プロンプト

- 先頭に採点に使うモデル（バックテスト区分と同じく、モデルとプロンプトを並べる）
- 固定のひな形（編集不可）と、差し込む場所
- 使用中の版の採点の基準を元に編集する。試し採点は保存も集計への反映もしない
- 試す記事は既定で最新の1件（ボタンは「最新のニュースで試す」）。「試す記事を選ぶ」のモーダルで、直近100件（ニュース画面と同じ並び）から5件まで選べる。選ぶとボタンは「選んだ記事で試す」になり、「最新の1件に戻す」で既定へ戻す
- 結果は記事ごとに、試した点数と理由の下に保存済みの点数と理由（採点した版）を並べる。採点済みでなければ「採点済みでない」
- 「vN として保存」は新しい版を足すだけで、使用中の版は変えない。版の説明は任意（空なら「画面から編集」）
- 版の履歴から「使用する」で切り替える。「差分」で選んだ版から使用中の版への差分を行単位で出す

### 取得

- 取得元の一覧（名前・言語・URL・最後に取得した時刻か失敗の理由）、有効/無効の切り替え、削除（確認あり）
- 取得元の追加（名前・RSS の URL・言語）
- 取得間隔（5〜1440 分）
