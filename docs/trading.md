# 自動取引（ペーパー）

自動取引がオンの間、運用する戦略を常駐で動かす。フェーズ4ではペーパー（最新の実データで模擬売買）だけ動く。ライブはまだ選べない。

## 売買の1ステップ

バックテストとペーパーは同じ処理（`packages/core/src/trading.ts`）で売買する。同じ戦略がどのモードでも同じ動きをするようにするため。

- 1ステップは「約定の反映 → 期限切れの指値の取消 → 戦略の評価と注文の作成」
- 違うのは約定の判定だけ。バックテストは足、ペーパーは受信した約定データで決める
- 買いは約定の時点で手数料込みの額が現金に足りなければ取り消す（どのモードも同じ）。成行は約定価格が発注後に決まるため、指値は同時に出した買いが先に約定して足りなくなることがあるため
- 保有はロット（約定した買い1件ぶん）の並びで持つ。売りは売るロットを指定し、そのロット全量を売る。往復はロット1件の買いと売りで、損益は売りの受け取り − 買いの支払い（どちらも手数料込み）
- 買いの注文を出すときは、未約定の買いが全部約定したときの支払い（手数料込み、成行は判定時の現在値で見積もる）を現金から除いて足りるかを見る
- ロットを持つ前に保存した口座は、保有を1ロットとして読む
- 指値を取り消すまでの M 本は、発注時刻から戦略の粒度の足 M 本ぶんの時間で数える

## 実行

- オンにすると、戦略の粒度の次の足の終わりに最初の評価をする。その後は戦略が返す次の判定時刻に評価する
- 自分の注文が約定したら、次の判定時刻を待たずに評価し直す（1秒ごとの見回りで）
- 評価のたびに、戦略の粒度の足（確定した足と、終わったばかりの足または途中の足）と、今の集計ルールで計算した AI 判定を渡す
- オンにするたびに戦略の state は初めからにする。保有と未約定の注文は口座に残っている
- オン中に運用中の戦略の条件を保存し直すと、次の判定から新しい条件を使う
- オフにすると新しい注文を出さない。未約定の注文は取り消さず、約定や期限切れの取消は続く
- 運用する戦略が無いか、条件が足りない（戦略の入力検証を通らない）とオンにできない
- オン中は運用する戦略を変えられない。動かしている戦略が削除されたら自動取引をオフにする（未約定の注文は残す）
- 1日の損失上限（`docs/strategies.md`）に達したら、その日は新しい買いを出さない。売りは続け、自動取引はオンのまま
- オン中は全画面の上部にペーパーの帯（黄）と、開始からの損益（円・%、保有を今の価格で評価した分を含む）、動かしている戦略名を出す。帯を押すと取引画面へ移る

## 仮想の約定（ペーパー）

- 買いの指値は、指値以下の価格で他の売買が成立したら指値で約定する。数量は見ない
- 成行は注文後に最初に成立した売買の価格で約定する
- 手数料は指値・成行とも 0.1%（バックテストの既定と同じ仮置き）

## 止まっていた間

- サーバーや価格の収集が止まっていた間は約定を判定しない（その間は約定しなかった扱い）。つなぎ直したときに遡って取る約定も使わない
- 価格の収集が止まっている間は判定しない（古い価格で注文しないため）。過ぎていた判定は、再起動や収集の復帰の後に1回だけ行う
- 口座（現金・保有・未約定の注文）・戦略の state・次の判定時刻は DB に置き、再起動しても続きから動く

## 口座

- 開始時の資金は既定で 100万円・0 BTC
- 「リセット」で現金・保有・未約定の注文を開始時の状態へ戻す。開始時の資金はリセットのときに決める（1円以上）。自動取引がオフのときだけできる
- リセットで未約定の注文は「口座のリセットで取消」として取り消す。過去の注文・約定・判断の記録は消さない

## 記録

- 注文は発注から約定・取消までを1件で持ち、発注した判断・戦略を付けて残す。削除しない
- 判断の記録（時刻・現在値・口座・注文・理由・state）と、そのときの AI 判定3つ（戦略が使わない判定も）を評価のたびに残す。保持期間（既定 90日、`docs/settings.md` の「データの保持」）を過ぎたものは消す。注文を出した判断は消さない

## 取引画面

`/trades`。スマホは下部タブの「取引」、PC はサイドバーから開く。

- 上部にペーパーの成績を出す。口座をリセットした時点以降が対象（「成績」参照）
- 自動取引の注文を新しい順に出す。モード（すべて・ペーパー・ライブ）、状態（すべて・約定・注文中・取消）、売買（すべて・買・売）で絞り込む
- 約定・取消・発注のうち最後の状態の時刻（JST）の日ごとにまとめる
- 売りの行には、売るロットの買値を「買値 ○○ のロット」と添える（バックテスト結果の注文の一覧も同じ）
- 絞り込んだ件数と、実現損益（売りの約定の損益）の合計を出す。一覧は新しい順に 1000 件までで、件数と合計はすべてを数える
- 行の右端は損益があれば損益、無ければモードの印（ペーパーは黄、ライブは赤）
- 5秒ごとに読み直す

### 成績

口座をリセットした時点（リセットしていなければ口座を作った時点）以降の約定から出す。5秒ごとに読み直す。

- 損益（円・%）: 総資産 − 開始時の資金。総資産は現金と保有を今の価格で評価した額（売りの手数料は含めない）
- 総資産・現金・保有 BTC・確定損益（往復の損益の合計）・評価損益（損益 − 確定損益）
- 勝率・最大DD・損益比率（PF）・取引回数・平均保有。数え方はバックテストの成績と同じ（往復の手数料込みの損益で勝ち負けを決め、未決済は含めない）
- 最大DD は約定の直後（約定価格）・1時間足の終値・今の時点で資産を評価して測る
- 今の価格は直近の約定。まだ無ければ保存済みの最後の1分足の終値。どちらも無く保有があれば損益・総資産は「—」

### 注文の詳細

ホームと取引画面で共通。バックテスト結果の注文の詳細と同じ内容に、「このときの判定」（発注した判断のときの AI 判定3つ）を足す。対応する売買があれば、そちらへ移れる。

## API

| API | 内容 |
|---|---|
| `GET /api/trading/status` | オン/オフ・モード・戦略・次の判定時刻・口座（今の価格で評価した総資産を含む） |
| `POST /api/trading/start` | `{ mode: "paper" }` でオンにする |
| `POST /api/trading/stop` | オフにする |
| `POST /api/trading/reset` | `{ initialCash }` で口座をリセットする |
| `GET /api/trading/performance` | `mode`（既定 `paper`）の口座のリセット以降の成績 |
| `GET /api/trading/orders` | 注文の一覧（新しい順）。`mode`・`status`・`side` で絞り込み、`limit` で件数を決める（既定・上限 1000）。条件に合う全件の件数と実現損益の合計も返す |
| `GET /api/trading/orders/:mode/:id` | 注文と、発注した判断のときの AI 判定 |
