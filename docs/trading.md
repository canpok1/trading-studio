# 自動取引（ペーパー）

自動取引がオンの間、運用する戦略を常駐で動かす。フェーズ4ではペーパー（最新の実データで模擬売買）だけ動く。ライブはまだ選べない。

## 売買の1ステップ

バックテストとペーパーは同じ処理（`packages/core/src/trading.ts`）で売買する。同じ戦略がどのモードでも同じ動きをするようにするため。

- 1ステップは「約定の反映 → 期限切れの指値の取消 → 戦略の評価と注文の作成」
- 違うのは約定の判定だけ。バックテストは足、ペーパーは受信した約定データで決める
- 成行の買いは約定の時点で手数料込みの額が現金に足りなければ取り消す（どのモードも同じ）
- 指値を取り消すまでの M 本は、発注時刻から戦略の粒度の足 M 本ぶんの時間で数える

## 実行

- オンにすると、戦略の粒度の次の足の終わりに最初の評価をする。その後は戦略が返す次の判定時刻に評価する
- 自分の注文が約定したら、次の判定時刻を待たずに評価し直す（1秒ごとの見回りで）
- 評価のたびに、戦略の粒度の足（確定した足と、終わったばかりの足または途中の足）と、今の集計ルールで計算した AI 判定を渡す
- オンにするたびに戦略の state は初めからにする。保有と未約定の注文は口座に残っている
- オン中に運用中の戦略の条件を保存し直すと、次の判定から新しい条件を使う
- オフにすると新しい注文を出さない。未約定の注文は取り消さず、約定や期限切れの取消は続く
- 運用する戦略が無いか、条件が足りない（戦略の入力検証を通らない）とオンにできない

## 仮想の約定（ペーパー）

- 買いの指値は、指値以下の価格で他の売買が成立したら指値で約定する。数量は見ない
- 成行は注文後に最初に成立した売買の価格で約定する
- 手数料は指値・成行とも 0.1%（バックテストの既定と同じ仮置き）

## 止まっていた間

- サーバーや価格の収集が止まっていた間は約定を判定しない（その間は約定しなかった扱い）。つなぎ直したときに遡って取る約定も使わない
- 価格の収集が止まっている間は判定しない（古い価格で注文しないため）。過ぎていた判定は、再起動や収集の復帰の後に1回だけ行う
- 口座（現金・保有・未約定の注文）・戦略の state・次の判定時刻は DB に置き、再起動しても続きから動く

## 口座

- 開始時の資金は既定で 100万円・0 BTC
- 「リセット」で現金・保有・未約定の注文を開始時の状態へ戻す。開始時の資金はリセットのときに決める（1円以上）。自動取引がオフのときだけできる
- リセットで未約定の注文は「口座のリセットで取消」として取り消す。過去の注文・約定・判断の記録は消さない

## 記録

- 注文は発注から約定・取消までを1件で持ち、発注した判断・戦略を付けて残す。削除しない
- 判断の記録（時刻・現在値・口座・注文・理由・state）と、そのときの AI 判定を評価のたびに残す。削除しない

## API

| API | 内容 |
|---|---|
| `GET /api/trading/status` | オン/オフ・モード・戦略・次の判定時刻・口座 |
| `POST /api/trading/start` | `{ mode: "paper" }` でオンにする |
| `POST /api/trading/stop` | オフにする |
| `POST /api/trading/reset` | `{ initialCash }` で口座をリセットする |
| `GET /api/trading/orders` | 注文の一覧。`mode`・`status`・`side` で絞り込める |
| `GET /api/trading/orders/:mode/:id` | 注文と、発注した判断の記録 |
