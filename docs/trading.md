# 自動取引（デモ）

自動取引がオンの間、その戦略を常駐で動かす。フェーズ4ではデモ（最新の実データで模擬売買）だけ動く。リアルはまだ動かせない。

## 戦略ごとの口座

複数の戦略を実レートで同時に検証するため、自動取引は戦略ごとに持つ。戦略1つが口座1つを持つ（`docs/adr/0031-strategy-owns-trading-account.md`）。

- 戦略ごとにモード・口座・オンオフ・戦略の state・次の判定時刻を持つ（`trading_runs` の1行）。戦略どうしは影響しない（同じ約定データで、それぞれの口座の注文を約定させる）
- モードは今はデモだけ。リアルの扱いはリアル取引の実装時に決める
- 同時にオンにできるのは5つまで
- 口座は戦略を作ったときに、開始時の資金を既定にしたデモで作る（統合前からある戦略の口座は移行で作った）
- 戦略の削除（`docs/strategies.md`）で口座も消す。注文・判断の記録は分析用のエクスポートのために残す（口座の行も消さずに削除済みにする）
- 統合前の運用（ホームのタブ。`docs/adr/0020-trading-run-per-tab.md`）は、それぞれ使っていた戦略の口座に引き継いだ。リアルの運用はデモにし、戦略が無い運用は未約定の注文を「戦略と運用の統合で取消」として取り消して削除済みにした

## 売買の1ステップ

バックテストとデモは同じ処理（`packages/core/src/trading.ts`）で売買する。同じ戦略がどのモードでも同じ動きをするようにするため。

- 1ステップは「約定の反映 → 期限切れの指値の取消 → 戦略の評価と注文の作成」
- 違うのは約定の判定だけ。バックテストは足、デモは受信した約定データで決める
- 買いは約定の時点で手数料込みの額が現金に足りなければ取り消す（どのモードも同じ）。成行は約定価格が発注後に決まるため、指値は同時に出した買いが先に約定して足りなくなることがあるため
- 保有はロット（約定した買い1件ぶん）の並びで持つ。売りは売るロットを指定し、そのロット全量を売る。往復はロット1件の買いと売りで、損益は売りの受け取り − 買いの支払い（どちらも手数料込み）
    - 一部利確（`docs/strategies.md`）だけはロットの一部を売る。買いの支払いを売った量で按分し、残りは同じロット（買値・買った時刻・最高値を引き継ぐ）として持つ。売りの注文の損益はその売りの分だけ
    - 往復は買い1件ごとに1件で、ロットを閉じた売りの時点で数える。損益は一部利確の売りの損益を含めた合計、保有時間は買いから最後の売りまで。一部利確の後にロットが残っている間は、往復（勝率・取引回数）には数えず、確定損益と1日の損失上限には数える
- 買いの注文を出すときは、未約定の買いが全部約定したときの支払い（手数料込み、成行は判定時の現在値で見積もる）を現金から除いて足りるかを見る
- ロットを持つ前に保存した口座は、保有を1ロットとして読む
- 指値を取り消すまでの M 本は、発注時刻から選んだ足の M 本ぶんの時間で数える

## 実行

- オンにすると、バックテストで進める足（`docs/backtests.md`）と同じ粒度の次の足の終わりに最初の評価をする。その後は戦略が返す次の判定時刻に評価する
- 自分の注文が約定したら、次の判定時刻を待たずに評価し直す（1秒ごとの見回りで）
- 評価のたびに、条件で使う足ごとの足（確定した足と、終わったばかりの足または途中の足）、トレーリングストップ・最高値からの ATR の倍数の最高値に使う前回の評価からの1分足、今の評価ルールで計算した市場評価を渡す。採点の記録が始まる前は判定を渡さない（データなし）
- オンオフは戦略ごと。オンにするたびに戦略の state は初めからにする。保有と未約定の注文は口座に残っている
- 条件はオン中と保有がある間は変えられない（`docs/strategies.md`）
- オフにすると新しい注文を出さない。未約定の注文は取り消さず、約定や期限切れの取消は続く
- 条件が足りない（戦略の入力検証を通らない）とオンにできない。リアルの口座はオンにできない
- 動かしている戦略が見つからなくなったら、その口座をオフにする（未約定の注文は残す）
- 1日の損失上限（`docs/strategies.md`）は戦略ごとの口座で数える。達したら、その日はその戦略で新しい買いを出さない。売りは続け、自動取引はオンのまま
- オンの戦略がある間は全画面の上部にデモの帯（黄）と、通算損益（円・%、保有を今の価格で評価した分を含む）、動かしている戦略名を出す。帯を押すとホームの稼働中の最初のタブへ移る
    - 2つ以上オンなら「デモ N件稼働中」と、損益の合計（% は開始時の資金の合計に対して）、戦略名を「・」でつないで出す

## 仮想の約定（デモ）

- 買いの指値は、指値以下の価格で他の売買が成立したら指値で約定する。数量は見ない
- 成行は注文後に最初に成立した売買の価格で約定する
- 手数料は指値・成行とも 0%（Coincheck の取引所の BTC/JPY と同じ。バックテストの既定も同じ）

## 止まっていた間

- サーバーや価格の収集が止まっていた間は約定を判定しない（その間は約定しなかった扱い）。つなぎ直したときに遡って取る約定も使わない
- 価格の収集が止まっている間は判定しない（古い価格で注文しないため）。過ぎていた判定は、再起動や収集の復帰の後に1回だけ行う
- 戦略ごとの口座（現金・保有・未約定の注文）・戦略の state・次の判定時刻は DB に置き、再起動しても続きから動く

## 口座

- 口座は戦略ごと。開始時の資金は既定で 100万円・0 BTC
- 「リセット」で現金・保有・未約定の注文を開始時の状態へ戻す。開始時の資金はリセットのときに決める（1円以上）。自動取引がオフのときだけできる
- リセットで未約定の注文は「口座のリセットで取消」として取り消す。過去の注文・約定・判断の記録は消さない

## 記録

- 注文は発注から約定・取消までを1件で持ち、口座・発注した判断・戦略を付けて残す。削除しない。注文の id は口座の中で振る
- 判断の記録（時刻・現在値・口座・注文・理由・state）と、そのときの市場評価（戦略が使わない判定も。採点の記録が始まる前は残さない）を評価のたびに残す。保持期間（既定 90日、`docs/settings.md` の「データの保持」）を過ぎたものは消す。注文を出した判断は消さない

## 注文・約定の一覧

ホーム（`docs/home.md`）の注文・約定のパネル。選んでいる戦略の注文だけを出す。以前の取引画面（`/trades`）はホームへ統合し、その URL はホームの同じモードの最初のタブへ移る。

- 自動取引の注文を新しい順に10件出し、「さらに表示」で10件ずつ足す。状態（すべて・約定・注文中・取消）、売買（すべて・買・売）で絞り込む。絞り込みを変えると10件に戻り、タブを切り替えると絞り込みも戻る
- 約定・取消・発注のうち最後の状態の時刻（JST）の日ごとにまとめる
- 売りの行には、売るロットの買値を「買値 ○○円 のロット」と添える（バックテスト結果の注文の一覧も同じ）
- 売りの行と注文の詳細には、どの条件のグループで売ったかと成り立った条件の名前をバッジで出す（例: 「損切り: EMA12/48下抜け」。条件の名前はバックテスト結果の条件の要約と同じ）。一部利確（「一部利確: +8%」）と利確は明るい橙、損切りは暗い赤茶（売り系は暖色、買い系は寒色。ホームの発動価格と揃える）。バックテスト結果も同じ
- 買いが2つ以上の戦略で出した買いの行と詳細には、買いの名前をバッジ（灰色）で出す（`docs/strategies.md`）。バックテスト結果も同じ
    - 売りの注文には、発注時に利確・損切りのどちらで出したかを記録する。記録を始める前の売りは判断の理由の文から読み、読めなければグループ名を出さない
- 絞り込んだ件数と、実現損益（売りの約定の損益）の合計を出す。一覧は新しい順に 1000 件まで足せ、件数と合計はすべてを数える
- 行の右端は損益があれば損益、無ければ状態（約定・注文中・取消）
- 5秒ごとに読み直す

## 成績

ホームの口座情報・成績のパネルで出す数字の数え方。戦略の口座をリセットした時点（リセットしていなければ口座を作った時点）以降の約定から出す。5秒ごとに読み直す。

- 損益（円・%）: 総資産 − 開始時の資金。総資産は現金と保有を今の価格で評価した額（売りの手数料は含めない）
- 総資産・現金・保有 BTC・確定損益（往復の損益の合計）
- 勝率・最大DD・損益比率（PF）・取引回数・平均保有。数え方はバックテストの成績と同じ（往復の手数料込みの損益で勝ち負けを決め、未決済は含めない）
- 最大DD は約定の直後（約定価格）・1時間足の終値・今の時点で資産を評価して測る
- ガチホ（リセットした時刻を含む1分足（まだ無ければ1時間以内で最初の1分足）の始値で買い、今の価格まで持っていた場合）の損益率を、損益の評価に使う。手数料は含めない
- 各数値に付ける評価のバッジは、バックテストの「成績の評価」と同じ基準
- 今の価格は直近の約定。まだ無ければ保存済みの最後の1分足の終値。どちらも無く保有があれば損益・総資産は「—」

## 注文の詳細

ホームの一覧とチャートの印で共通。バックテスト結果の注文の詳細と同じ内容に、「このときの市場評価」（発注した判断のときの市場評価。統合前のトレンドの値は出さない）を足す。対応する売買があれば、そちらへ移れる。

## API

| API | 内容 |
|---|---|
| `GET /api/trading/strategies` | 戦略ごとの自動取引の状態（戦略を作った順。`id` は戦略の id）。オン/オフ・モード・次の判定時刻・口座（今の価格で評価した総資産を含む）・条件を変えられない理由 |
| `POST /api/trading/strategies/:id/start` | オンにする |
| `POST /api/trading/strategies/:id/stop` | オフにする |
| `POST /api/trading/strategies/:id/reset` | `{ initialCash }` で口座をリセットする |
| `GET /api/trading/strategies/:id/performance` | 口座のリセット以降の成績 |
| `GET /api/trading/strategies/:id/watch` | 戦略を今の価格で試算した見張り（`docs/home.md` の「戦略の見張り」）。価格がまだ無ければ `watch` が null |
| `GET /api/trading/orders` | 注文の一覧（新しい順）。`strategy`（戦略の id）・`status`・`side` で絞り込み、`limit` で件数を決める（既定・上限 1000）。条件に合う全件の件数と実現損益の合計も返す |
| `GET /api/trading/orders/:strategy/:id` | 注文と、発注した判断のときの市場評価 |

戦略の作成・名前・削除は戦略の API（`docs/strategies.md`）で行う。
