# バックテストの AI アドバイス

バックテストの結果から、AI（Gemini）が結果の分析と改善案を作る。結果画面の「AI アドバイス」で「アドバイスを作る」を押すと作り始める。

## 生成

- 作れるのは終わったバックテストだけ。同じ実行で作成中なら新しく始めない
- サーバーで作り、画面を離れても続く。画面は作成中だけ3秒ごとに問い合わせる。サーバーが途中で止まった作成は、次の起動時に失敗として残す
- API キーはニュースの採点と共用（設定の「全般」）。モデルと指示は設定の「バックテスト」で、採点とは別に持つ。選べるモデルは採点と同じで、既定は Gemini 3.8 Flash
- 待つ時間は 180 秒まで（採点は 60 秒）。応答が長く、Pro のモデルは時間がかかるため

## 保存

- 実行ごとに最新の1件だけ持つ。作り直すと、作り終えたときに置き換える
- 作成中と失敗の間は前のアドバイスを残して出す。失敗の理由も出す
- 本文と一緒に、作った時刻・モデル・指示の版・作ったアプリのバージョン（ビルド日時）を持ち、本文の下に出す。サーバーの処理（約定の扱いなど）もアドバイスに影響するため

## AI に渡すもの

- 実行の条件（期間・口座・判定と約定に使った足）、戦略設定、成績、注文の一覧（発注の理由を含む）
- 実行の条件・戦略設定・評価ルールは、画面の見出しと項目名（例: 「買い注文する条件」の「短期EMA 12 本が 長期EMA 48 本を上抜けた」）で書く。改善案を画面でそのまま設定し直せる言葉で出してもらうため、プログラムの項目名や JSON は渡さない
- 値動きは戦略が参照する足（戦略の粒度）で渡す。判定の条件を使う戦略だけ、足ごとの判定と実行時の評価ルールも渡す
- 足が 3,000 本を超えるときは、全体を 1,500 本以下に収まる最も細かい粗さの足にまとめ、残りの枠で注文（発注・約定・取消）の前後 10 本ずつを戦略の足で渡す。枠に収まらなければ前後の本数を半分ずつ減らし、それでも収まらなければ古い注文の前後から載せられる分だけ載せる（`docs/adr/0010`）

## プロンプト

- ひな形（出力の形式を含む）は固定。編集できるのは「指示」だけで、採点の基準と同じく版を足していき、使用する版を選ぶ。版を変えても作成済みのアドバイスはそのまま
- 改善案は画面の見出しと項目名で書くよう、ひな形で指示する
- 出力は見出しが固定（結果の分析・うまくいった点・悪かった点・改善案）。構造化出力で JSON の形を強制し、どれかが空なら失敗にする
- 見出しと一緒に「改善案を反映した後の戦略設定」も構造化出力で出させる。改善案で変えない項目は元の値を写させる。画面の項目との対応は出力の形の説明（description）で伝え、本文にはプログラムの項目名を出させない

## 改善版でバックテストする

- アドバイスの本文の下の「改善版でバックテストする」で、改善版の戦略を入れた実行画面へ移る。期間・口座は元の実行と同じ、名前は「元の名前（改善版）」（40 文字に収まるよう元の名前を切る）
- 改善版の戦略は、戦略として検証し、元の戦略設定から変わっているときだけ使う。使えなければボタンを押せなくして理由を出す。アドバイスの本文は成功として残す（本文だけでも役に立つため、全体を失敗にしない）
- 改善版の戦略を持たない作成済みのアドバイスは、ボタンを押せなくして「作り直すと使える」と出す
- 変えてよいのは戦略設定の全項目（足の粒度・判定の間隔・注文量・最大ポジション数・1日の損失上限・条件・買いの注文）。期間と口座は変えない（元の結果と比べられなくなるため）
- 実行画面では「戦略設定」の横に「AI の改善版」と出し、元の実行から変えた項目を見出しごとに出す（AI が意図せず値を変えても気づけるようにするため）。変更点は閉じるかテンプレートを読み込むと消える
