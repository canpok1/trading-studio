# 設定画面

設定画面（`/settings`）は、メニューに合わせた区分（全般・バックテスト・ニュース。並びもメニューと同じ）に分ける。複数のメニューで使う設定は「全般」に置く。表示中の区分は URL（`?section=`、全般なら無し）に持つ。

## 全般

- 画面の色（OS に合わせる・ライト・ダーク）。選んだ設定はブラウザに保存する
- Gemini の API キー: 設定済みか未設定かと保存した日時だけを出し、キーそのものは出さない。入力は伏せ字。上書きと削除（確認あり）ができる
- OpenAI 互換の接続先: Bifrost などの集約サービスの URL と API キー。下の「OpenAI 互換の接続先」に詳しく書く
- データの保持: 古いデータを消すまでの期間（判断の記録・バックテストは 30・90・180・365・730日・無期限、足・ニュース・採点は 1・2・3・5・10年・無期限）。「データの保持」に詳しく書く

## OpenAI 互換の接続先

採点とアドバイスで、Gemini 直結のほかに OpenAI 互換 API（Chat Completions）の接続先のモデルを使えるようにする（`docs/adr/0027`）。

- URL（`http://` か `https://` で始まる。末尾の `/` は外して保存）と API キー（任意。接続先がキーを求めるときだけ）を保存する。キーは Gemini と同じく DB に平文で持ち、画面へは返さない。キー欄が空なら保存済みのキーを残すが、URL を変えたときは消す（前の接続先のキーを別の宛先へ送らないため）
- 「接続を確かめる」で接続先の `/models` を読み、つながればモデルの件数を出す
- 削除（確認あり）で URL とキーを消す
- 採点・アドバイスのモデルの選択欄は、Gemini 直結の固定の3モデルと、接続先の `/models` から取った一覧を見出しで分けて並べる。一覧は選択欄を開くたびにサーバー経由で取り直す（キーはブラウザへ渡さない）。入力すると、空白で区切った語をすべて含むモデルだけに絞り込む
- 接続先のモデルは `openai:<接続先のモデル名>` の形で保存し、採点・アドバイスの記録にもこの形で残す。Gemini 直結のモデル名と区別するため
- 一覧を取れないとき（接続先が止まっている・未設定）も、選択欄にその理由を出し、保存済みのモデルはそのまま表示・使用する
- 選んだモデルの接続先が使えない（Gemini の API キーが無い・OpenAI 互換の接続先が無い）と、採点は止まり、アドバイスは作れない。理由を出す
- 接続先を保存・削除したとき、採点が OpenAI 互換のモデルを使っていれば、失敗した採点をすぐやり直す
- 送る形: `model` に印を外したモデル名、`messages` にプロンプト1つ、`response_format` に JSON Schema（`strict` なし）。形の定義は Gemini の書き方で持ち、送るときに標準の JSON Schema へ変換する。変換ではオブジェクトに `additionalProperties: false` を付け、数の範囲（`minimum`・`maximum`）は説明文へ移す（Claude が求める・受け付けないため）。接続先が構造化出力を 400 で断ったら、`response_format` を外し形を JSON Schema の文章でプロンプトに足して問い合わせ直す。断ったモデルは、サーバーを再起動するまで最初から文章で渡す（Claude は任意の項目が 24 個までなど、アドバイスの形は複雑さの上限を超える）。応答は、構造化出力を無視して囲みや前置きを付けるモデルに備え、最初の `{` から最後の `}` までを読む。待つ時間は Gemini と同じ（採点 60 秒・アドバイス 180 秒）

## データの保持

DB の肥大化を防ぐため、毎日 4:00（JST）に保持期間を過ぎたデータを消す。サーバーの起動時に前回から実行時刻を過ぎていれば1回実行する。前回の削除を記録していなければ、起動した後の最初の 4:00 に実行する。

| 対象 | 既定 | 消し方 |
|---|---|---|
| 判断の記録（自動取引） | 90日 | 判断した時刻が期間より前のものを消す。注文を出した判断は、注文の詳細の「そのときの判定」に使うので消さない |
| バックテストの実行 | 無期限 | 実行を始めた時刻が期間より前のものを、結果・アドバイスごと消す。実行中とアドバイスの生成中は消さない。データセットのまとめた実行は、含む実行がすべて消えたら消す |
| 足・ニュース・採点 | 5年 | 期間より前の足（全粒度）と、公開時刻が期間より前のニュースを採点・採点し直しごと消す。開始が期間より前の相場データは、相場ごとに開始が最も新しい1件と、データセットに入っているものだけ残して消す。残した相場データの期間と、その前の下表の範囲の足とニュースは消さない（指標の計算と市場評価で期間より前を使うため。`docs/adr/0034`） |

- 残した相場データの開始より前に残す範囲。足は粒度ごとに、指標の上限で要る前の足（850本、`docs/backtests.md`）と31日の長いほう

| 対象 | 残す範囲 |
|---|---|
| 1分・5分・15分足 | 開始の31日前〜終了 |
| 1時間足 | 開始の850時間（約35.4日）前〜終了 |
| 4時間足 | 開始の850本（約142日）前〜終了 |
| 日足 | 開始の850日前〜終了 |
| ニュース・採点 | 開始の31日前〜終了 |

- 自動取引の注文は成績に使うので消さない
- 足・ニュースの期間は年で数える（実行した時刻の N 年前）。1年分の足は全粒度で約57MB、うち約78%が1分足（`docs/adr/0025`）
- ニュースを消した境目を覚え、境目の31日後までは市場評価の記録が無いものとして扱う（遡って使う記事が欠けているため。`docs/backtests.md`）。残した相場データで実行するときは、その相場データの開始から記録があるものとする。消している途中で止まっても扱いが変わらないよう、境目は消す前に覚える
- ニュースを消した期間（開始の31日前が境目より前の期間）は、足を取り込み直しても相場データにしない
- 足を消した期間はインポート画面で欠損として出る
- 消した期間の判断の記録は分析用エクスポートに出ない
- カードに次回と前回の削除（日時・件数・失敗の理由）、DB の大きさ、テーブルごとの行数を出す
- 消しても DB ファイルは縮まない。空いた領域は次の書き込みで再利用され、ファイルがそれ以上大きくならない。縮める処理（VACUUM）は、実行中に他の書き込みを止めてしまうので行わない

## バックテスト

AI アドバイスに使うモデルとプロンプトの指示（版の履歴と使用する版の切り替え）。`docs/advice.md`。

## ニュース

評価ルール・プロンプト（採点に使うモデルを含む）・取得・予定（買いの条件「予定の前後でない」に使う予定の取得元と評価基準）・精度（ニュース画面の精度の測り方）。`docs/news-page.md` の「設定画面の「ニュース」区分」。
