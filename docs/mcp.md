# Claude Code からの接続（MCP）

ローカルの Claude Code から戦略と、ニュースの AI 採点の基準を相談して改良するための MCP サーバー。backend の `/mcp`（Streamable HTTP、セッションを持たない）で動く。

## つなぎ方

Tailscale に接続した PC で、一度だけ次を実行する。`<サーバー>` は画面を開くときのアドレス（`<mini-pc のマシン名>.<tailnet 名>.ts.net`）。

```bash
claude mcp add --transport http trading-studio https://<サーバー>/mcp
```

認証は付けない。画面と同じく tailnet 内の端末からだけ届く（`docs/adr/0004`）。

## 道具

| 道具 | 内容 |
|---|---|
| `get_guide` | 条件セット（戦略の params）の項目・単位・範囲とひな形の例 |
| `list_strategies` `get_strategy` | 戦略の一覧・1件。条件は画面の文言と JSON の両方で返す。条件を変えられない理由（自動取引がオン・保有か未約定の注文がある）を `lock` で返す |
| `create_strategy` | 条件セットから新しい戦略を保存する |
| `update_strategy` | 戦略の条件を置き換える。`lock` がある戦略は変えられない |
| `get_data_coverage` | 価格データの粒度ごとの範囲と欠損の数 |
| `run_backtest` | 戦略か条件セットでバックテストを実行し、終わるまで（最大 2 分）待って成績を返す。待ちきれなければ実行中のまま返す。市場評価に使う採点の版と、予定の前後の条件に使う予定の評価基準の版を指定できる。期間は日付か相場データで渡す |
| `list_segments` | 相場データの一覧。相場で絞れる |
| `list_datasets` `save_dataset` | データセット（相場データを束ねたもの）の一覧・保存（作成と上書き） |
| `run_dataset` `get_dataset_run` | データセットの相場データごとにバックテストを実行し、終わるまで（最大 2 分）待って合算した成績と相場データごとの成績を返す・まとめた実行1件。採点の版と予定の評価基準の版を指定できる |
| `list_backtests` | バックテストの履歴。画面の履歴のタブと同じく、単独の実行とデータセットでまとめた実行を1行ずつ並べ、キーワード・失敗を隠す・損益順で絞れる |
| `get_backtest` `get_backtest_orders` | バックテスト1件の条件と成績・注文（発注の理由と往復の損益を含む） |
| `get_backtest_advice` | 結果画面の AI アドバイス（本文・改善案を反映した条件セット・作った時刻とモデル）。作るのは画面から |
| `list_auto_trading` | 戦略ごとの自動取引の一覧（`id` は戦略の id）。モード・稼働中か・次の判定時刻・今日の確定損失、デモは口座・含み損益・成績も |
| `list_trading_orders` | 戦略の注文・約定（発注の理由・往復の損益・利確/損切りの別・発注したときの市場評価）。状態・売買で絞れる |
| `get_strategy_watch` | ホームの「次の動き」「戦略の見張り」（条件ごとの成立・今の値・発動価格） |
| `get_market_price` | 現在値・24時間の変化率・価格の収集の状態 |
| `get_price_bars` | ホームのチャートの足と、足ごとの市場評価（チャートの背景）。新しいほうから指定した本数まで |
| `get_scoring_setup` | 採点のプロンプトの固定のひな形・採点の基準の全版と使用中の版・モデル・評価ルール・採点の状態 |
| `get_market_evaluation` | 市場評価（評価・平均点・件数）と市場評価の内訳。時点を指定できる（ニュース画面の今の市場評価・評価詳細のタブの内訳） |
| `preview_aggregation_rule` | 評価ルールの案での今の市場評価。保存しない（設定画面の評価ルールの「この設定での今の市場評価」） |
| `get_market_evaluation_analysis` | 市場評価の分析。件数と、精度ごと・評価ごと・評価×値動きの件数、使った設定の「精度」の値。時点と、プロンプトの版・アプリのバージョン・モデルでの絞り込みを指定でき、版・モデルごとの件数も返す（評価詳細のタブ） |
| `get_event_setup` | 予定の取得元と取得の状態・暦のそろっている終わり・重要度の判断のプロンプトの固定のひな形・予定の評価基準の全版と使用中の版・未判断と失敗の件数（設定画面の「ニュース」→「予定」）。取得元と評価基準の変更は道具にしない |
| `list_events` | 予定と重要度の判断（重要度・理由・状態）。使用中の版での判断。期間・重要度の下限で絞れる（ニュース画面の予定のタブ）。判断し直しは道具にしない |
| `list_news_scores` | ニュースと採点（点数・持続・理由・基準の版・モデル・Ver）・市場評価での重み・記事ごとの精度・画面から頼んだ採点し直しの状態（採点し直し中・順番待ちと先の件数・再試行待ち・失敗）。ニュース画面と同じ条件（期間・キーワード・影響の大きさ・持続・評価に使用中・並び順）で絞れる。1000 件目まで |
| `trial_scoring` | 採点の基準の案で、指定した過去のニュース（5件まで、省けば最新の1件）を採点し直す。保存も集計への反映もしない（設定画面のプロンプトの試し採点） |
| `rescore_news` | バックテストの期間の市場評価に使うニュースを、保存済みの版で採点し直して保存する（`docs/news.md` の採点し直し）。採点は裏で進むので、呼び直して進み具合を見る |
| `add_scoring_criteria` `set_active_scoring_criteria` | 採点の基準を新しい版として保存する・使用する版を切り替える（`docs/adr/0013`） |

- 自動取引のオン/オフ・リセット、自動取引がオンか保有がある戦略の変更、戦略の削除、API キーや設定の変更は道具にしない。口座や実資金に効く操作は画面から人が行う（`docs/adr/0012`）
- 例外は採点の基準の版の保存と切替（`docs/adr/0013`）。切り替えると次に採点するニュースから使い、自動取引の判定にも効くので、道具の説明で切り替える前に利用者へ確認を取るよう求めている
- 返す情報は画面の機能と一致させ、画面に無い分析は持たない（`docs/adr/0022`）。成績には画面のバッジと同じ5段階の評価（`grades`）を添える。リアルの口座は画面と同じく口座・成績・注文・戦略の見張りを返さない。精度の期間・測る長さ・値動きの段階の境目は設定の「精度」の値を使う（`docs/news-page.md`）
- 運用の採点を置き換える採点し直し（ニュース画面の記事ごとのボタン）と、AI アドバイスを作る操作（API の料金がかかる）は道具にしない
- 入力の検証は画面と同じ（戦略の名前・条件セット・バックテストの実行条件）
- 時刻は JST の ISO 8601 で返す。入力はタイムゾーン付きの ISO 8601 か `YYYY-MM-DD`（JST の 0:00）

## 時刻

- 市場評価の時点（`at`）を省くと今。先の時刻は今として扱う
- `list_news_scores` の期間は公開時刻で絞る。重みと「評価に使用中」は、`to` が今より前ならその時刻、それ以外は今の市場評価で測る（ニュース画面で日付を指定したときと同じ）
