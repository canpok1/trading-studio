# ニュースと採点

AI判定の材料にするニュースを RSS で集める。取得元と間隔の決定は `docs/adr/0008`。

## 収集

サーバーが動いている間、設定された間隔（既定 15分、5〜1440分）で有効な取得元の RSS を順に取得する（ON/OFF は無い）。

- 起動直後に1回収集し、以後は「前回の収集を始めた時刻 + 間隔」ごとに収集する。間隔と取得元の変更は再起動なしで次の収集から反映する。追加した取得元は、次の収集を待たずにすぐ取得する
- 読める形式は RSS 2.0・RSS 1.0・Atom。見出し・URL・概要・公開時刻を読む。見出しか URL（http/https）が無い記事は捨てる
- 概要は HTML のタグを除き、500文字で切る。本文は取りに行かない
- 公開時刻が無いか読めない記事は、取得時刻を公開時刻とする
- 見出し・概要・URL・取得元の名前・言語・公開時刻・取得時刻を保存する
- 同じ URL の記事は1件として扱う（別の取得元でも）。別の URL なら同じ話題でも別件
- ニュースは削除しない（バックテストの材料のため）。取得元を削除しても、集めたニュースは残す
- 1つの取得元の取得は20秒で打ち切る

## 取得元

- 名前（40文字以内）・URL（http/https）・言語（日本語・英語）で追加する。同じ URL の取得元は追加できない
- 有効・無効を切り替えられる。無効にすると失敗の記録も消す
- 既定の取得元は初回の起動時に1度だけ入れる。削除した既定の取得元は、次の起動で戻さない

## 状態

- 取得元ごとに、最後に成功した時刻と、失敗していればその理由と失敗が続いている最初の時刻を持つ。成功すると失敗の記録は消える
- 有効な取得元が無いか、有効な取得元がすべて失敗しているときは停止中とし、理由といつからかを返す

## 採点

集めたニュースを Gemini で1件ずつ採点する。モデルの決定は `docs/adr/0008`。

- 取得した順に1件ずつ採点する。問い合わせの間は5秒以上空ける（無料枠の回数制限に当たらないため）。採点は1件につき1回で、採点済みは採点し直さない（版やモデルを切り替えても）
- 新しさの時刻（公開時刻。取得時刻より後なら取得時刻）が集計の期間より前の記事は、保存するが採点しない（集計の対象外）
- プロンプトは固定のひな形に、ニュース（情報源・公開時刻・見出し・概要）と採点の基準を差し込む。並びは `<news>` → `<criteria>` → 依頼・出力形式
- 観点（trend・risk・sentiment）ごとに 0〜100 の整数か null（関係なし）、comment は採点の理由の文字列。構造化出力で形を強制し、受け取った後も検証する。合わなければ失敗
- 採点結果に、点数・comment・採点した時刻・採点の基準の版・モデルを保存する。削除しない
- 失敗したら 30秒・2分・10分の間隔で3回まで自動で再試行する。それでも失敗なら「採点に失敗」として止め、画面の再試行で採点し直す
- API キーは画面から保存し、DB の設定に平文で持つ（`docs/adr/0009`）。API はキーそのものを返さず、設定済みかと保存した日時だけを返す。空白を含むものと 200 文字を超えるものは保存しない
- API キーが無ければ採点を止め（ニュースは未採点のまま残る）、収集は続ける。保存すると次の採点から再開し、失敗したものと再試行を待っているものもすぐ採点し直す。保存・削除すると続いている失敗の表示も消す
- 採点の状態: API キーが無いか、直近の採点が続けて失敗している間は停止中とし、理由といつからかを返す。採点に成功すると動作中に戻る

### 採点の基準

- 採点の基準（プロンプトのうち編集できる部分）は上書きせず版で持つ。新しい版として保存しても、使用する版は切り替えない
- 使用する版を切り替えると、次に採点するニュースから使う
- 初回の起動時に初版を入れて使用中にする

### 試し採点

- 最新のニュース（公開時刻が最も新しいもの）を、渡した採点の基準と今のモデルで採点する。保存も集計への反映もしない
