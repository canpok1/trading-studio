# エクスポート

記録をファイルで書き出す画面（`/export`）。スマホでは「その他」の中、PC ではサイドバーに置く。書き出しは2つ。

- **分析用（ZIP）**: AI 判定の精度と戦略の成績の分析を Claude に頼むためのデータ。サーバーは自宅にあり外から読めないので、画面からダウンロードしてチャットに添付する
- **価格データ（CSV）**: 保存済みの足のバックアップ。取り込みと同じ形式で、そのまま取り込み直せる

2つを1つの ZIP にまとめない。バックアップの CSV は展開せずに取り込み直せることが目的で、粒度・既定の期間（全期間）も分析用（1分足・直近30日）と違うため。過去データの画面にはエクスポートの画面への案内だけを置く。

## 分析用（ZIP）

- 期間を JST の日付で選ぶ。既定は今日を含む直近30日。期間は [開始日の 0:00, 終了日の翌日の 0:00)
- バックテストは、開始時刻が期間内の完了した実行の一覧から選んだものだけ入れる。選ばなければバックテストの表は列名だけになる
- 表ごとの CSV と、列の意味・単位・期間で絞る基準を書いた `README.md` を1つの ZIP にする。README は表の定義から作り、全ての列の説明を載せる
- ファイル名は `trading-studio-analysis-<開始日>-<終了日>.zip`（日付は JST の `YYYYMMDD`）
- API キーなどの設定値は入れない

### 入れる表

AI 判定の精度向上用

| ファイル | 中身 | 期間の絞り方 |
|---|---|---|
| `news.csv` | ニュースと採点（3観点の点数・理由・採点時刻・基準の版・モデル・状態）。失敗・未採点・古いため採点しないものも状態付き | 新しさの時刻が、期間の始まりの集計期間ぶん前から期間の終わりまで（期間の最初の判定に使うものを含めるため） |
| `scoring_criteria.csv` | 採点の基準の全版の本文と、今使っている版 | 全部 |
| `aggregation_rule.csv` | 今の集計ルール | — |
| `judgments.csv` | 1時間足の終わりの時刻ごとの判定・平均点・件数。今の集計ルールで計算する。採点の記録が始まる前は空 | 期間内。書き出した時刻より後は入れない |
| `candles_1m.csv` | 1分足。取り込みと同じ形式（価格データの CSV と同じ書き出し処理） | 期間内 |

戦略の勝率アップ用

| ファイル | 中身 | 期間の絞り方 |
|---|---|---|
| `strategies.csv` | 今ある戦略の条件 | 全部 |
| `paper_decisions.csv` | 自動取引の判断の記録と、そのときの AI 判定 | 判断した時刻が期間内 |
| `paper_orders.csv` | 自動取引の注文（約定・損益） | 発注した時刻が期間内 |
| `backtest_runs.csv` | 選んだ実行の条件・集計ルール・成績 | 選んだもの |
| `backtest_orders.csv` `backtest_trades.csv` `backtest_decisions.csv` | 選んだ実行の注文・往復の取引・判断ログ | 選んだもの |

### 書式

- UTF-8・LF。値に `,` `"` 改行を含むときは `"` で囲む
- 時刻はエポックミリ秒の列と、列名に `_jst` を付けた JST の文字列（`2026-09-26T12:00:00.000+09:00`）の列の2つで出す。`candles_1m.csv` は取り込み形式どおり JST の文字列だけ
- 金額は円、数量は satoshi の整数のまま出す。`candles_1m.csv` の出来高だけは取り込み形式どおり BTC の小数
- 条件のセット・発注の内容・戦略の状態・集計ルール（バックテストの写し）は JSON の文字列で1列に入れる

## 価格データ（CSV）

- 粒度（保存済みの足がある粒度だけ）と期間を選ぶ。期間の既定は、選んだ粒度の保存済みの全期間
- 列は取り込みと同じ（`docs/market-data.md` の「CSV の形式」）。日時は JST
- 欠損は埋めない。自動で作った足のうち、元の細かい足の最後より後ろまで続く作りかけの足は出さない
- ファイル名は `btcjpy-<粒度>-<最初の足の日>-<最後の足の日>.csv`
