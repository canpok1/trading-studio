# 過去データ

バックテストに使う BTC/JPY の足を CSV で取り込む。

## CSV の形式

```
日時,始値,高値,安値,終値,出来高
2026-09-26T12:00:00.000+09:00,13500000,13520000,13490000,13510000,1.25
```

- 取り込むときに足の粒度（1分足・5分足・15分足・1時間足・4時間足・日足）を指定する
- 日時は RFC 3339 形式でタイムゾーンが必須（`+09:00` や `Z`）。小数秒は省略できる。タイムゾーンの無い日時はエラーにする
- 日時はその粒度の足の開始時刻へ切り下げる（1分足の `12:00:01` は `12:00:00` の足）
- 1行目の日時が読めなければヘッダーとして読み飛ばす
- 価格は円。小数は四捨五入する。出来高は BTC で、satoshi（1e-8 BTC）へ四捨五入する
- 1行でも不正な行があれば1行も保存しない。エラーは行番号・該当行・理由を返す（最大100件）

## 保存のルール

- 同じ粒度・同じ日時に取り込んだ足があれば、上書きせずに読み飛ばして件数に数える
- 取り込んだ足より粗い粒度の足を自動で作る（1分足 → 5分足 → 15分足 → 1時間足 → 4時間足 → 日足の順に1段ずつ）。日足・4時間足は JST 0:00 で区切る。細かい粒度の足は作らない
- 取り込んだ足を優先する。自動で作る足は、その粒度の足が無い日時か、以前に自動で作った足だけを置き換える
- 取り込みはサーバー内のジョブとして進め、同時に動くのは1つ。検証中・保存中は中止でき、中止するとその取り込みで保存した足を消す。粗い足の作成中は中止できない
- 欠損は「その粒度で本来あるはずの時刻の足が無い」連続区間。最初の足と最後の足の間で数える
- サーバーが取り込みの途中で止まった場合、次の起動時にその取り込みを失敗として残す

## 価格収集

サーバーが動いている間は、Coincheck の BTC/JPY の約定を受け続けて1分足を作る（ON/OFF は無い）。取得方式は `docs/adr/0007`。

- 約定は公開 WebSocket の取引履歴チャンネルで受ける。板情報チャンネルも購読し、届いたことを接続が生きている印にする
- 1分足は、その分が終わって2秒後に確定して保存する。ただし最後に何かを受け取った時刻までの分しか確定しない（接続が黙って死んでいる間に足を作らないため）
- 約定の無い分は直前の終値で横ばい・出来高 0 の足にする。収集が止まっていた期間は足を作らず、欠損として残る
- つながった直後は、公開 API の直近の約定（100件）で遡れる範囲を補う。つながった分は途中からしか約定が分からないので、補えた範囲の最初の分は作らない
- 切断されたら自動で再接続する。間隔は1秒から失敗のたびに倍にし、上限は1分。1分以上続いた接続が切れたら1秒に戻す
- 60秒なにも届かないとき、または30秒たっても購読が始まらないときは、止まったとみなしてつなぎ直す
- 保存した足の出どころは「収集」。同じ日時の足は、取り込んだ足も含めて上書きする
- 収集した1分足から粗い足を作る。細かい足が1本も欠けずに揃っている区切りでは、取り込んだ粗い足も上書きする。欠けている区切りでは取り込んだ足を残す（完全な足を不完全な足で置き換えないため）
- 収集した足は、取り込んだ足と同じく過去データ画面の帯グラフ・欠損とバックテストに使う
- 同じ ID の約定は1回だけ数える。確定済みの分に遅れて届いた約定は捨てる

## 最新価格とチャートの足（ホーム）

- 現在値は直近の約定の価格。まだ約定を受けていなければ、最後に保存した1分足の終値
- 24時間の変化は、現在値と「24時間前の時刻以前で最も新しい1分足」の終値から出す。その足が無ければ出さない
- 収集の状態（動作中・接続中・停止中、止まった理由、いつから、次の再接続）と形成中の1分足も返す
- 画面は5秒おきに問い合わせる
- チャートの足は粒度と期間（1日・1週・1か月・全期間）で取る。期間の前に EMA の計算用の足を足せる（上限1000本）。足が5万本を超える組み合わせは返さない
