# 0024. データセットは足を写さず期間と相場のラベルで持ち、ラベルはルールで付ける

- ステータス: 採用
- 日付: 2026-10-08

## コンテキスト

バックテストの期間は日付で指定していた。利用者から、毎月直近2か月のデータをデータセットとして保存し、「〜相場」のラベルを1つ自動で付けてバックテストに使いたいという要望があった（利用者案は、肥大化を防ぐためラベル1種につき最新のみ保存）。

足は取り込んだ分も収集した分も DB に残り、定期削除の対象でもない（docs/settings.md「データの保持」）。

## 決定

- データセットは期間（JST の月初から2か月）とラベル・騰落率・日ごとの値動きの標準偏差だけを持つ。足は写さず、バックテストは期間内の足を読む
- 起動時・毎日 4:00（JST）・取り込みの後に、まだ作っていない期間を作る。1分足が期間の分の95%以上そろっている期間だけ作る
- データセットはすべて残す（ラベルごとに最新のみにはしない）
- ラベルは日足からルールで付ける。日ごとの騰落率（終値の対数変化）の標準偏差が 3.5% 以上なら乱高下相場、それ以外は期間の騰落率が +12% 以上で上昇相場、−12% 以下で下落相場、その間はレンジ相場
- 閾値は GMO の BTC/JPY 日足の直近5年（2021-10〜2026-10）で、1日ずつずらした2か月の窓 1,765 件に当てて決めた（利用者の指示）。乱高下 9%・上昇 34%・下落 22%・レンジ 34%
- バックテストの期間は「データセット｜期間を指定」で切り替える。データセットを選ぶと日付の欄は出さない。結果にデータセットとそのときのラベルを残す

## 結果

- データセットを足しても DB はほとんど増えない
- 同じラベルの別の時期で戦略を試せる
- 1分足が無い期間（1時間足だけ取り込んだ過去など）はデータセットにならない
- アプリの日足は JST 0:00 区切りで、閾値を決めた GMO の日足（6:00 区切り）と境目の窓の判定がずれることがある

## 検討した代替案

- 足をデータセットごとに写す: 同じ足を二重に持つだけで肥大化する
- ラベル1種につき最新のみ残す（利用者の初案）: 期間だけなら容量の心配が無く、同じ相場の別の時期で試せなくなる
- AI でラベルを付ける: 同じデータでも結果が揺れ、理由を追えない
- 騰落率だけで上昇・下落・レンジの3種: 2か月だと大半が ±10% を超え、レンジがほぼ付かない
- 標準偏差 3.0%: 窓の 29% が乱高下になり、上位25%点（3.06%）に近すぎる
- 2019〜2026 の全期間・±15%・4% で決める: 利用者が直近5年を基準にしたいと判断
- 月初の1回だけ作る: 月初にサーバーが止まっていると、その月のデータセットができない
- データセットを選ぶと日付の欄に入る（入力欄は残す）: データセットで試すときに日付を触る必要がなく、分けたほうが分かりやすい（利用者の指摘）
