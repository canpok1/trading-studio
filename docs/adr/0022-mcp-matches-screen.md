# 0022. MCP の道具は画面の機能と一致させ、MCP 独自の分析はやめる

- ステータス: 採用
- 日付: 2026-10-08

## コンテキスト

ADR 0013 で、MCP にだけ採点・判定を値動きと突き合わせる分析（点数と騰落率の相関・向きの当たり率・判定ごとの騰落率）を足した。その後、画面に記事ごとの精度と「市場評価の分析」（評価詳細のタブ）ができ、同じ問いに別の物差しで答える機能が2つ並んだ。MCP 経由で Claude Code に分析させるとき、画面で見ている数字と食い違うと話がかみ合わない。

## 決定

- MCP が返す情報は画面の機能と一致させる。画面に無い MCP 独自の分析は持たない（利用者の判断、2026-10-08）
  - 削除: `evaluate_news_scores`・`evaluate_judgments`・`list_news_scores` の騰落率
  - 追加: 市場評価と内訳（`get_market_evaluation`）・評価ルールの案での今の市場評価（`preview_aggregation_rule`）・市場評価の分析（`get_market_evaluation_analysis`）・`list_news_scores` の重み・精度と画面と同じ絞り込み
- 分析の期間・測る長さは画面と同じく設定の値を使い、道具の引数では変えない
- 運用の採点を置き換える採点し直し（ニュース画面の記事ごとのボタン）は道具にしない。口座に効く操作は画面から人が行う ADR 0012 の線に合わせる
- 機能の説明（`get_guide` の条件の項目説明など）は画面の機能ではないが、AI が道具を使うための説明書きなので残す

## 結果

- 画面で見ている数字をそのまま Claude Code に渡して相談できる
- 相関係数など画面に無い切り口が要るときは、先に画面の機能として足す

## 検討した代替案

- 独自の分析を残し、画面と同じ分析を足す: 道具は増えるが、物差しが2つあると結論が食い違う
- 期間・測る長さを道具の引数で変えられるようにする: 設定を変えずに比べられるが、画面と数字がずれる
