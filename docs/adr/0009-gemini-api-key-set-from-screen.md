# 0009. Gemini の API キーは画面から保存して DB に持ち、画面へは返さない

- ステータス: 採用
- 日付: 2026-09-26

## コンテキスト

採点に使う Gemini の API キーは、環境変数 `GEMINI_API_KEY` で渡していた。自宅サーバーのコンテナの設定を書き換えて再起動する必要があり、キーを替えるたびに手間がかかる。ユーザーから、画面で設定し、保存した値は再表示せず削除か上書きだけできるようにしたいと要望があった（2026-09-26）。

## 決定

- API キーは AI判定画面の「収集と採点」タブで保存・上書き・削除する。環境変数は読まない
- DB の `settings` に平文で保存する
- API はキーそのものを返さず、設定済みかどうかと保存した日時だけを返す。入力欄は伏せ字にする
- 採点はキーを問い合わせのたびに読むので、保存・削除は再起動なしで次の採点から効く

## 結果

- キーの設定と交換が画面だけで済む
- DB のファイルを読める人にはキーが見える。DB は自宅サーバーの中にだけある
- 実取引までは画面を認証なしで LAN に公開している（ADR 0004）。LAN 内の人はキーを上書き・削除できるが、読み出すことはできない。保存するときのキーは HTTP で平文のまま LAN を流れる
- 既に環境変数でキーを渡していた場合は、画面から保存し直す必要がある

## 検討した代替案

- 環境変数のまま: 変更にコンテナの再設定と再起動が要る。要望に合わない
- 画面での設定に加え、環境変数も読む: 2か所に置けると、どちらが使われているか画面から分かりにくい。まだ誰も環境変数で運用していないので、1か所に絞った
- DB に暗号化して持つ: 復号の鍵を同じサーバーに置くことになり、DB を読める人から守る効果が薄い
