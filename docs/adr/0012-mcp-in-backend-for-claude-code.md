# 0012. Claude Code から戦略を相談できるよう、backend に MCP を内蔵する

- ステータス: 採用
- 日付: 2026-09-27

## コンテキスト

戦略を AI と相談しながら改良したい。クラウドの Claude からは自宅サーバーに届かず、今は分析用の ZIP を書き出して添付している（`docs/export.md`）。自宅 LAN 内の PC で動く Claude Code なら、backend に直接つなげる。戦略とバックテストの操作は REST API にそろっている。

## 決定

- backend に MCP サーバーを `/mcp`（Streamable HTTP、セッションなし）として内蔵する。PC 側は `claude mcp add --transport http` の1行でつなぐ
- 道具は読み取りと、戦略の新規作成・運用中でない戦略の条件変更・バックテストの実行に限る。自動取引のオンオフ・運用する戦略の切替と変更・削除・設定は出さない。ライブ取引の実装後もこの線を変えない
- 認証は付けず、公開範囲は画面と同じ（ADR 0004）。Tailscale へ切り替えるときに合わせて見直す

## 結果

- PC に何も入れずにつながり、サーバーの自動デプロイで道具も更新される
- backend に `@modelcontextprotocol/sdk` と `zod` の依存が増える
- 自宅 LAN につながる端末からは、画面と同じく戦略を作り変えられる。運用する戦略と口座には触れない
- 条件の種類を足したら、`packages/backend/src/mcp/guide.ts` の説明も足す（型で漏れに気づける）

## 検討した代替案

- PC で動く MCP（stdio）を別パッケージにして REST API を叩く: backend を変えずに済むが、PC に clone と bun が要り、サーバーと版がずれうる
- MCP を作らず、スキルに API の使い方を書いて curl で叩く: すぐ試せるが、条件の JSON を手で組むので誤りやすく、自動取引のオンオフを含むあらゆる API を叩けて操作を絞れない
- MCP にだけトークン認証を付ける: 画面が認証なしで同じ操作をできるので、守りが増えない
