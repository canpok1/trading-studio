# 0005. 画面遷移に React Router、CSS に Tailwind CSS v4 を使い、E2E は Playwright で流す

- ステータス: 採用
- 日付: 2026-09-26

## コンテキスト

フェーズ1で画面（バックテスト・戦略設定・過去データ・表示設定）を作る（Issue #16）。スマホ幅を前提に、PC ではサイドバーに切り替える。配色はキャンバスで決めたライト / ダークの2組を使い、チャート（Lightweight Charts）にも同じ色を渡す。

## 決定

- 画面遷移は React Router。URL で画面を分け、再読み込みしても同じ画面に戻る
- CSS は Tailwind CSS v4（Vite プラグイン）。キャンバスの配色は `@theme` の CSS 変数（`--color-bg` など）で定義し、ダークは `html.dark` で同じ変数を上書きする
- ライト / ダークの初期値は OS の設定に従い、手動で選んだらブラウザ（localStorage）に保存する。サーバーには持たない
- E2E は Playwright。Chromium だけで、スマホ幅（390px）と PC 幅（1280px）の2通りを流す。backend を空のテスト用 DB で起動し、ビルド済みの画面を開く。ファイル名は `*.e2e.ts`（`bun test` が `*.spec.ts` を拾うため）

## 結果

- 配色を CSS 変数で持つので、Tailwind のクラスが効かないチャートにも `getComputedStyle` で同じ色を渡せる
- クラス名が長くなる。部品に切り出して繰り返しを減らす
- E2E は CI で毎回ビルドしてから流すため、CI の時間が延びる

## 検討した代替案

- CSS Modules：Web 標準ではなくビルドツールの機能。標準外を使うなら Tailwind を使いたいというユーザー判断で見送った
- 素の CSS：標準だが、画面が増えるとクラス名の衝突と使われない定義の整理が負担になる
- 画面遷移を状態だけで持つ（モックの方式）：URL が変わらず、再読み込みや戻るボタンで画面が保てない
