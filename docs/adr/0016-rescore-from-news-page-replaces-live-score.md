# 0016. ニュース画面の採点し直しは運用の採点を置き換え、元の採点は版の採点として残す

- ステータス: 採用
- 日付: 2026-09-30

## コンテキスト

採点の基準（プロンプト）を直したあと、過去の記事も新しい基準で採点し直して、今の市場評価に効かせたい（利用者の要望）。

- 採点は記事ごとに1回で、版を切り替えても採点済みは採点し直さない
- 0015 の採点し直しは、バックテストで版を比べるためのもので、運用の採点（ニュース画面・今の市場評価・ペーパー取引）は変えない

## 決定

- ニュース画面から、記事1件か絞り込みの条件に当てはまるもの（1000件まで）を、使用中の版で採点し直す。版は選ばない
    - 2026-10-08 変更: 絞り込みの条件でまとめて採点し直すのはやめ、記事1件ずつにした。全件が対象になりやすく、採点の API の1日の回数制限に当たりかねないため（利用者の要望）。記事ごとのボタンは誤操作を避けるため「詳しく」を開いたときだけ出す
- 採点し直したら運用の採点を置き換える。判定に使い始める時刻（採点時刻）は変えない
- 元の採点は、その版の採点し直しの結果（`news_rescores`）として残す。バックテストで元の版を選べば元の点数で比べられる
- 採点し直しは 0015 と同じ仕組み（`news_rescores`）に「置き換える」印を付けて頼む。その版の採点が既にあれば問い合わせずに置き換える

## 結果

- 基準を直した効果が、今の市場評価とペーパー取引にすぐ出る
- バックテストの「運用どおり」に、過去の時点ではまだ無かった版の採点が混ざる。使い始める時刻は元のままなので、ニュースを実際より早く知っていたことにはならない。版ごとの効果を比べるときは版を選ぶ
- 採点の分析・エクスポートの採点時刻は、置き換えた採点でも元の採点時刻のまま（置き換えた時刻は別に持つ）

## 検討した代替案

- 見比べるだけにする（運用の採点は変えず、ニュース画面で表示する版を切り替える）: 基準を直しても今の市場評価に効かない。利用者が置き換えを選んだ
- 使い始める時刻を採点し直した時刻にする: 過去の記事が今から集計に入り、古いニュースが今の評価を動かす
- 元の採点を捨てる: 新旧の版を同じ記事で比べられなくなる
