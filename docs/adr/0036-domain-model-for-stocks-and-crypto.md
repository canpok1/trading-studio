# 0036. 株と仮想通貨を同じ中核で扱い、違いを市場のルールと外部への接続に閉じ込める

- ステータス: 採用（同時に買いが成り立ったときの並び順での優先は `0037` で置き換え）
- 日付: 2026-10-23

## コンテキスト

利用者が、BTC/JPY に加えて日本株・米国株でもバックテストとデモを試したいと考えた（リアルは検討中）。今のコードは銘柄という概念を持たず、数量は satoshi、金額は円、相場は24時間休みなく続く前提で書かれている。利用者は、株への対応を前提にドメインモデル（DDD）を先に固め、次に仮想通貨の部分をリファクタリングし、その後に株へ対応する、という順で進めると決めた。

## 決定

- 資産の種類ではなく責務で境界を分ける（売買の判断・銘柄と市場のルール・市場データ・執行と口座・市場評価・成績）。株と仮想通貨の違いは市場のルール（取引時間・休場・売買単位・通貨・値幅制限）と外部への接続（データの取得元・発注先）に閉じ込める。根拠: 売買の周りは共通になりそう（利用者）
- 1つの戦略で複数の銘柄を扱える設計にし、銘柄ごとの売買の判断と資金配分を分ける。根拠: システムトレードでは複数銘柄をよく扱い、将来必要になりうる（利用者）
- 1つの戦略は1つの市場だけを扱う。根拠: シンプルにしたい。複数の市場は複数の戦略の同時運用で足りる（利用者）
- 信用取引・空売りは今は考えない（将来はありうる）（利用者）
- 注文量は金額で決め売買単位に切り捨てる（数量での指定も残す）。根拠: 価格の違う銘柄に同じルールを当てるため（利用者）
- 同時に買いが成り立ち資金が足りなければ、銘柄の並び順で優先する。根拠: シンプルにするため（利用者）
- 指標は分割・配当を補正した価格、約定と損益は実際の価格で計算する。分割は保有の数量を、配当は現金を動かす。根拠: 約定価格をデモ・リアルと食い違わせないため（利用者）
- 金額は通貨の、価格・数量は銘柄ごとの最小単位の整数で持つ。根拠: 桁が膨らまず、刻みの検査も兼ねられるため（利用者）
- 市場評価・DVOL・予定イベントは市場に紐づけ、中身は当面 BTC 専用。根拠: 株向けの評価は未検証のため（利用者）

## 結果

- 戦略の条件や売買の処理を資産の種類ごとに二重に持たずに済む
- 中核が暗黙に置いている前提（satoshi・円・24時間・JST 0:00 の日の区切り）を、銘柄と市場のルールから受け取る形へ改める必要がある。`.claude/rules/values.md` もリファクタリングの中で書き換える
- 戦略をまたいだ合計（通算損益など）を円で出すには為替のデータが要る

## 検討した代替案

- 資産の種類ごとに境界を分ける: 売買の判断を2つ持つことになる
- 1つの戦略で複数の市場を扱う: 取引時間の重ならない市場の時刻合わせと、通貨をまたぐ資金配分が要り、複雑になる
- 全部を補正済みの価格で計算する: 約定価格が実際と合わなくなる
- 全銘柄の価格を共通の細かい単位で持つ: 桁が膨らみ、刻みの検査も別に要る
