# 0029. 予定イベントの暦は設定した取得元（iCal）から自動で取得し、暦切れの扱いは条件で選ぶ

- ステータス: 採用
- 日付: 2026-10-16

## コンテキスト

買いの条件「予定イベントの前後でない」（PR #225）は、FOMC 声明・議事要旨・米 CPI・米雇用統計・日銀会合の日時を暦として使う。PR #225 では暦を 2022〜2026 年の分だけリポジトリに持ち、暦の無い期間は買いを判定しないようにした。この2点は利用者に諮らずに決めていたため、利用者が改めて判断した（2026-10-16）。

## 決定

- 暦は、設定に持つ取得元（iCal の URL）から自動で取得する。根拠: 手動での更新を避けたい。iCal を選んだのは汎用的な形式だから（利用者）
- 取得元の既定は持たない。根拠: どこが最適か今の時点で分かっていない（利用者）
- リポジトリに持つ 2022〜2026 年の暦と、取得した暦は残す。根拠: バックテストで使えるようにする（利用者）
- 暦がそろっていない期間（暦切れ）を成立とみなすかは、条件ごとに選べるようにする。根拠: 市場評価の条件で「データなし」を対象にするか選べるのと同じ形にしたい（利用者）

## 結果

- 取得元を設定するまでは、2026 年末で暦切れになる

## 検討した代替案

- 暦をリポジトリにデータで持ち、年に一度手で足す（PR #225 の形）: 手動での更新を避けたい（利用者）
- 暦切れでは常に買いを判定しない（PR #225 の形）: 市場評価の「データなし」と同じく、条件として選べるようにしたい（利用者）
