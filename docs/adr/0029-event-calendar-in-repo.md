# 0029. 予定イベントの暦はリポジトリのデータとして持ち、暦の無い期間は買いを判定しない

- ステータス: 採用
- 日付: 2026-10-16

## コンテキスト

買いの条件「予定イベントの前後でない」には、FOMC 声明・議事要旨・米 CPI・米雇用統計・日銀会合の日時が要る。バックテストは 2022 年からの過去を、運用は今後の予定を見る。延期（2025 年の政府閉鎖など）は実際の公表日時で持つ必要がある。取引のルールを持つ core は外部に依存しない（`.claude/rules/core.md`）。暦が古いまま気づかず運用すると、条件が効かないまま買い続ける。

## 決定

- 暦は `packages/core/src/event-calendar.ts` にデータとして持ち、取得しない。時刻は UTC エポックミリ秒、米国は ET の夏時間を反映、時刻の無い日銀会合は JST の日の 0:00〜24:00
- 暦が全件を持つ期間（`EVENT_CALENDAR_RANGE`）を持ち、判定の範囲がこの外に掛かれば、その買いを判定しない（暦切れ）。理由は判断の記録とホームの「戦略の見張り」に出す
- 暦を足すときは一次資料（federalreserve.gov・bls.gov・boj.or.jp）から集め、期間の終わりを延ばす PR を出す

## 結果

- バックテストと運用が同じ暦を使い、結果が再現できる
- 年に一度ほど人手の更新が要る。忘れると暦切れで買いが止まるが、止まったことは画面で分かる
- 延期など予定の変更は、PR を出すまで反映されない

## 検討した代替案

- 公開の API・ページから定期取得する: BLS はこの環境から 403 で取れず、ページの形の変化で静かに壊れる。延期の扱いも自動では揃わない
- 暦切れを成立（買う）扱いにする: 条件が効いていないことに気づけない
- DB に持ち画面から編集する: 1人で年1回の更新には重く、バックテストの再現性が DB の状態に左右される
