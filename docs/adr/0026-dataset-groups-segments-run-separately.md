# 0026. データセットは相場データを束ねたものにし、相場データごとに別々に実行して成績を合算する

- ステータス: 採用
- 日付: 2026-10-10

## コンテキスト

`0024` の2か月の期間（当時の呼び名はデータセット）は、1件では取引回数が少なく成績が偶然に左右される。また同じ期間で調整を繰り返すと過剰最適化になる。複数の期間で同じ条件を試し、成績を合わせて見たいという要望があった（利用者）。

あわせて呼び名を見直した。束ねる側をデータセットと呼ぶほうが一般的な用法（標本を集めたもの）に合い、「テストスイート」は期待する結果を持つように読める（利用者の指摘）。

## 決定

- 2か月の期間を「相場データ」（コード・DB では segment）に改名し、相場データを名前を付けて束ねたものを「データセット」（dataset）とする。画面・ドキュメント・MCP・コード・DB の名前を揃える（利用者の指示）。英語名に market data を使わないのは、足の取り込み（`market-data`）と紛れるため
- データセットの中身は保存したまま変えない。同じ組で戦略を比べるため
- 実行は、相場データごとに通常のバックテストを1件ずつ順に実行し、まとめた実行として束ねる。期間はつながず、初期資金は相場データごとに戻す。それぞれの結果も見られるようにする（利用者の指示）
- 1件でも実行できない相場データがあれば全体を実行しない
- 合算は、取引回数・勝率・PF を全相場データの取引をまとめて数え、損益は平均と最悪、最大DD は最大のものにする。損益は足し合わせない
- 期間が重なる相場データは入れられるが、警告を出す

## 結果

- 戦略を複数の相場で試した成績を1画面で比べられる
- 隣り合う相場データは1か月重なるので、重ねたまま入れると成績が水増しされる。警告で知らせるだけで止めない
- 市場評価の記録が始まる前の相場データでは、市場評価の条件（「データなし」なし）を使う戦略を実行できない。当面は値動きだけの戦略向けになる

## 検討した代替案

- 期間をつないで1回のバックテストにする: 相場データごとの成績が見えず、資金の増減が次の期間に持ち越されて比べにくい
- 実行のたびに相場データを選ぶ（保存しない）: 比べるたびに選び直しになり取り違える
- 「相場ごとに最新N件」のような自動で中身が変わる組: 新しい相場データができると中身が変わり、過去の結果と比べられない
- 実行できる相場データだけ実行する: 組ごとの比較が崩れる
- 重なる相場データを禁止する: 数の少ない相場では、重ねないと件数が足りないことがある
- 束ねる側の名前を「テストスイート」「テストセット」「コレクション」にする: テストスイートは期待する結果を持つように読める。テストセットはデータセットと紛れる。利用者がデータセットを束ねる側にする案を選んだ
