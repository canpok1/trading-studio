# 0037. 1つの戦略で候補の銘柄を条件で絞り、順位で選んで売買する

- ステータス: 採用
- 日付: 2026-10-24

## コンテキスト

利用者が、1つの戦略で仮想通貨の複数の銘柄を扱い、条件のよさそうな銘柄を自動で選んで取引したいと考えた。将来は同じ仕組みを株に流用したい。ADR 0036 で「1つの戦略で複数の銘柄を扱う」「1つの戦略は1つの市場だけを扱う」は決めてあるが、どの銘柄を選ぶか・資金をどう分けるか・市場評価をどう銘柄に当てるかは決めていなかった。

Coincheck の取引所は 26 銘柄を扱うが、BTC 以外は出来高が小さく、買値と売値の差も広い（2026-10-24 に公開 API で確認。BTC 0.02%・ETH 0.09%・SOL 0.66%）。今のバックテストは成行を次の足の始値で約定させ、この差を計算していない。

## 決定

- 候補の銘柄すべてに買い条件を当て、成り立った銘柄を順位の上から買う。ADR 0036 の「資金が足りなければ銘柄の並び順で優先する」はこの順位で置き換える。根拠: 条件が成り立った銘柄の中で、よりよいものを選びたいため（利用者）
- 順位の決め方は戦略の設定に持ち、指標1つ（上昇率・RSI・ADX・出来高。粒度と期間を指定）と高い順・低い順で決める。根拠: まずはシンプルな仕組みから始めたいため（利用者）
- 候補の銘柄は戦略ごとに手で選び、選べるのは価格を収集している銘柄だけにする。根拠: まずはシンプルな仕組みから始めたいため（利用者）
- 戦略に同時に持つ銘柄数の上限を持ち、1銘柄に入れる金額は買いルールの注文量を使う。同じ銘柄の買い増しは今どおり許し、上限は持っている銘柄の数で数える。根拠: 新しい入力が上限1つで済み、資金を使い切るのを防げるため（利用者）
- 買値と売値の差を銘柄ごとに持ち、バックテストの成行の約定価格に反映する。根拠: BTC 以外は差が大きく、入れないとバックテストが実際より良く見えるため（利用者）
- ニュースの市場評価は銘柄ごとに分け、記事ごとの1回の AI の呼び出しで全銘柄ぶんを出す。根拠: 銘柄ごとに呼ぶと呼び出しの回数が爆増するため（利用者）
- AI には市場全体に1組、加えて記事が個別に関係する銘柄だけ1組ずつ点数を返させる。銘柄に対する記事の評価は、その銘柄の個別の点数があればそれ、無ければ市場全体の点数とする。根拠: 株への流用も自然にできそうなため（利用者）
- 過去の記事は銘柄ごとの形で採点し直す。根拠: 過去の期間のバックテストで銘柄ごとの評価を使うため（利用者）
- DVOL は BTC 専用とし、DVOL の条件を使う戦略は候補を BTC だけにする。他の銘柄の DVOL を入れるときは、その銘柄の専用とする。根拠: 今の DVOL は BTC に対する指標で、他の銘柄で使う理由がなく、間違って使うのを避けるため（利用者）
- 予定イベントは全銘柄に共通とする。根拠: 銘柄に依らないため（利用者）

## 結果

- 戦略への入力・バックテスト・デモ・画面を、候補の銘柄ごとの足・保有・成績を扱う形へ広げる必要がある
- 収集する銘柄とバックテスト用の過去データを、候補にする銘柄の分だけ足す必要がある
- 採点のプロンプトと点数の保存の形が変わり、過去の記事の採点し直しに AI の費用が一度かかる
- 株では銘柄が数千あり、AI に関係する銘柄をどう名指しさせるかは株対応のときに決める

## 検討した代替案

- 売買は1銘柄のまま、他の銘柄の価格・指標を条件で参照できるようにする: 使い所がない（利用者）
- 条件だけで選び、資金が足りなければ並び順で優先する: 銘柄同士を比べない
- 決まった時刻に順位を付け直して上位を持ち替える: 今の条件で買って条件で売る戦略と別の形になる
- 順位を複数の指標の重み付きの合計で決める: 設定が複雑になる
- 出来高などの基準で候補も自動で作る: 仮想通貨は銘柄が少なく効果が薄い。株のときに改めて考える
- 資産を上限で等分する・銘柄ごとに比率を決める: 買いルールの金額と二重に決まる・自動で選ぶことと矛盾する
- 銘柄ごとに AI を呼ぶ: 呼び出しの回数が爆増する
- 全銘柄に1組ずつ点数を返させる: 株で破綻する
- 関係する銘柄だけ点数を返させる: 全体に効く記事で全銘柄を並べさせることになる
