# 0014. AI 判定のトレンドをセンチメントへ統合し、観点をセンチメント・リスクの2つにする

- ステータス: 採用
- 日付: 2026-09-28

## コンテキスト

ニュースの AI 採点は、トレンド（上昇要因か下落要因か）・リスク・センチメント（楽観か悲観か）の3観点だった。入力はニュースだけで、採点の基準にも「価格そのものの推移ではなく、ニュースの材料で判断する」とある。

- 「トレンド」「上昇・レンジ・下落」は値動きの言葉で、実際のレートから判断するものと読める。戦略のひな形「トレンド追随」（EMA で組む）とも言葉がぶつかる
- ニュース分析の既存サービスでは、材料の強気・弱気をセンチメントと呼ぶ（RavenPack の Sentiment Score、CryptoPanic の bullish / bearish）。楽観・悲観の度合いは MarketPsych では Optimism など別の指標にしている
- トレンドとセンチメントは同じものを測っていて、独立した観点にする理由が薄い

## 決定

- 観点をセンチメント・リスクの2つにする。センチメントの定義は「BTC の価格にとって強気材料か弱気材料か」（旧トレンドの定義）。判定値は +2〜−2 の5段階のまま
- 過去の sentiment の点数は、マイグレーションでトレンドの点数に置き換える（旧センチメントは捨てる）。採点し直さずに過去とつながるため
- 戦略の条件のトレンド判定はセンチメント判定へ書き換える（上昇→+2・+1、レンジ→0、下落→−1・−2、データなし→データなし）。保存済みの戦略・バックテストの記録・改善版の戦略が対象
- 集計ルールのトレンドのしきい値は消す。自動取引の判断の記録にある過去のトレンドの値は残し、表示しない

## 結果

- 画面・条件・分析で、観点の名前が中身と業界の用語に合う
- 既定のしきい値では、トレンドの上昇（20 以上）とセンチメントの +1 以上（20 以上）は同じ境目になる。ただし下落は −20 以下、−1 は −20 未満なので、平均点がちょうど −20 のときだけ書き換えた条件の結果が変わる
- 旧センチメント（楽観・悲観）の点数は失われる

## 検討した代替案

- 名前だけ変える（「材料」「ニュースの方向」など）: 言葉の違和感は消えるが重複が残る。既存サービスにこの名前の例が無く、利用者にもしっくり来なかった
- トレンドを「強気／弱気」に改名して2つとも残す: 重複が残る
