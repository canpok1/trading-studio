# 0019. 買いを複数持ち、売りの条件・注文量・最大ロット数は買いごとに持つ

- ステータス: 採用
- 日付: 2026-10-01

## コンテキスト

戦略は「買い・一部利確・利確・損切り」の条件グループを1組だけ持っていた。押し目買いと突破買いのように、買い方ごとに出口を変えた戦略を1つで動かしたいという要望が出た（利用者の要望）。売りはすでにロット（買い1件）ごとに判定している（0011）。

## 決定

- 戦略は買いを 1〜5 個持つ。買いごとに 名前・1回の注文量・最大ロット数・買いの条件と注文・一部利確・利確・損切り を持つ。判定の間隔・1日の損失上限・損切り後に買わない本数は戦略全体に残す
- ロットと買いの注文は買いの id を持ち、ロットは買った買いの売り条件で売る。id を持たないロットは先頭の買いで売る
- 同じ判定で複数の買いが成立したら、買える（空き枠・約定待ちなし・資金あり）一番上の買いだけ注文する。連続買いの防止（一度外れてから買う）は買いごとに数える
- 買いを持つ前の戦略・結果は、買い1つとして読み替える
- 運用する戦略は、自動取引がオンの間と保有か未約定の注文がある間は、条件の変更・切り替え・削除をできなくする。保有ロットの買いが編集で消えるのを防ぐため（利用者の提案）

## 結果

- 戦略の JSON の形が変わる（`buys` の配列）。AI の改善版の構造化出力・MCP の説明・分析エクスポートも同じ形に合わせた
- 最大ロット数が買いごとなので、同時の保有の上限は買いごとの合計になる
- 成績は買いごとに分けない（必要になれば、注文の記録の買いの名前から足せる）

## 検討した代替案

- 注文量・最大ロット数を戦略全体に残す: 合計の上限が1か所で分かるが、押し目は小さく・突破は大きくのように買いごとに量を変えられない（利用者が買いごとを選択）
- 成立した買いを全部注文する: 同じ足で重複して買いすぎるため、上の1つだけにした
- 運用中の編集を許し、消えた買いのロットは先頭の買いで売る: 保有中のロットの売り方が編集で黙って変わるため、編集を止める方を採った
