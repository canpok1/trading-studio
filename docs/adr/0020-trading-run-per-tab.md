# 0020. 自動取引を運用（ホームのタブ）ごとに持ち、口座・オンオフ・戦略を運用ごとにする

- ステータス: 採用
- 日付: 2026-10-02

## コンテキスト

自動取引は口座（モードごとに1つ）・実行状態（1つ）・運用する戦略（1つ）を持ち、同時に動かせる戦略は1つだった。複数の戦略を実レートで同時に検証したいという要望が出た（利用者の要望）。ホームの「ペーパー｜ライブ」のタブを、戦略ごとに足せるタブにしたい。

## 決定

- 「運用」を新しく持ち、ホームのタブ1つにあたる。名前・モード・運用する戦略・口座・オンオフ・戦略の state・次の判定時刻を運用ごとに1行で持つ（`trading_runs`）。注文と判断の記録は運用の id で区別し、注文の id は運用の中で振る
- 運用は最低1つ・最大5つ。ライブは1つまで。同じ戦略を複数の運用で使ってよい
- 削除はオフのときだけ。未約定は取り消し、保有は捨てる。注文・判断の記録を分析用のエクスポートで運用の名前と出せるよう、運用の行は消さずに削除済みにする
- 戦略全体の「運用する戦略」の設定はやめ、運用ごとに選ぶ。戦略の条件のロックは、その戦略を使う運用のどれかがオンか保有を持つ間にする
- 以前の口座・実行状態・運用する戦略・注文・判断は、運用「ペーパー」（id 1）へ移す

## 結果

- 常駐の見回りは運用ごとに約定・期限切れ・評価を行う。1つの運用の失敗でほかの運用を止めない
- API は運用の id で指定する形（`/api/trading/runs/:id/...`）に変わり、モードで指定する API と `/api/strategies/active` はなくした
- 分析用のエクスポートの判断・注文に運用の id と名前が付く

## 検討した代替案

- 口座をモードごとのまま、戦略ごとに state だけ分ける: 損益が混ざり、戦略ごとの成績を比べられない
- タブの数を無制限にする: スマホのタブの並びと見回りの負荷を見て、5つで足りるとした（利用者が選択）
- ライブのタブを複数持てる: 実口座は1つで、残高を取り合う
- 削除で運用の行も消す: エクスポートで過去の注文がどのタブのものか分からなくなる
- 戦略画面の「運用する戦略」を残す: タブごとに選ぶので意味がなくなる（利用者が選択）
